## Итоговые сопоставимые замеры

Каждый запуск: 5 000 000 переходов, seed 42, GTX 1660 Ti, JAX 0.11.2, CUDA runtime 13.4.92, Python 3.12.3 в WSL Ubuntu 24.04. Запуски выполнялись последовательно, без конкурирующей GPU-задачи.

| compact-a | бои, наблюдение 118 | 11,489501 | 435 180 |
| baseline-f | исходные числовые правила | 8,023028 | 623 206 |

Потеря пропускной способности: **29,1997%**. На тот же бюджет требуется примерно на 41,24% больше времени learner. В обеих финальных парах падение превышает 7%; оно не объясняется одним шумным запуском.

Настройки PPO совпадают: 250 параллельных сред, rollout 100, 4 эпохи, 10 минибатчей, два скрытых слоя по 128 с tanh, gamma 0,99, GAE lambda 0,95, learning rate 0,0003, entropy coefficient 0,01. В каждом запуске 200 обновлений PPO и по 8 000 шагов оптимизаторов актёра и критика. Секции arch, system и network сохранённых конфигураций проверены на точное совпадение. Код learner не менялся.

Измерялся весь learner: среда, выбор действий, расчёт преимуществ и обновления PPO. Каждый вызов синхронизирован с GPU перед остановкой таймера. Первая исполняемая итерация включена; отдельного отбрасываемого прогрева нет. Компиляция, evaluation, запись логов и checkpoint исключены из этого времени и сохранены отдельно. Одинаковая методика применяется к обеим средам.

Один переход новой среды — перемещение на карте либо одно действие бойца, включая ход ИИ или завершение побега. Переходы не равны полным боям. В двух финальных боевых запусках 34,07326% переходов происходили в бою; это скорость обучения на смеси карты и боя, а не тест непрерывного боя. Наблюдение увеличилось с 52 до 118 значений, число действий — с 8 до 18, число параметров актёра и критика суммарно — с 47 753 до 65 939. Эти изменения отражают новую задачу, а не изменение размеров скрытых слоёв.

## Проверенные оптимизации

1. Первый вариант имел 178 значений наблюдения и давал 428 840 переходов/с.
2. Убрано повторное построение полной маски внутри шага: проверяется только выбранное действие. Для ветвей карты и боя используется общий вектор случайных чисел; объединён выбор состояния для неверных и терминальных действий. Два измерения дали 427 340 и 433 480 переходов/с — заметного устойчивого выигрыша не получилось.
3. Наблюдение сокращено до 118 значений без удаления нужных боевых сведений: убраны дубли максимального HP и старые числовые силы, состояние очереди объединено со знаком приоритета, подготовка/завершение побега объединены в одно значение. Финальные результаты приведены выше. Промежуточные checkpoint с наблюдением 178 поддерживаются.

Весь шаг, очередь, RNG, маски и автоматический сброс остаются на JAX/GPU через jit/vmap/scan. Число эпох, параллельных сред и минибатчей не сокращалось; CPU-симуляции и передачи состояния на CPU внутри обучения нет. Кэширование начальной фиксированной карты сохраняется, но поток случайности при сбросе обязательно обновляется.

Оптимизации дали небольшой выигрыш, но не вернули скорость в пределы 7%. Прежнее разрешение игнорировать этот порог для большого экспериментального прототипа Disciples не распространяется автоматически на текущую доработку.

Проверки охватывают прежние числовые правила, боевые действия, обе линии целей, очередность и ожидание, промахи, защиту, отступление, восстановление погибших, поражение, лимиты, маски, RNG при auto-reset, пакетные GPU-эпизоды и проход всей карты. 93 проверки прошли после первой оптимизации; затем прошли все 23 проверки боя, включая две добавленные проверки компактного наблюдения и полного маршрута. Итого покрыто 95 отдельных проверок.

Числа выше относятся к скорости, а не к доказанной сходимости. У checkpoint compact-b после 5 млн переходов sampled evaluation выиграл 798 из 1024 эпизодов (77,93%), а argmax — 0 из 1024. В просмотрщике сохранены три реальные JAX-записи: argmax с лимитом 2000, sampled-победа за 203 перехода и sampled-поражение за 123. Старый результат 33 млн на числовой карте не относится к боям.
