# CodeRabbit → Codex → повторное ревью → слияние

В Alian3785/jaxrep цикл запускают события GitHub Actions. Расписания нет.
Пользователь разрешил исправления, ответы в PR, обычные пуши и автоматическое
слияние проверенного PR в его текущую целевую ветку. CodeRabbit делает ревью;
Codex исправляет подтверждённые ошибки; доверенный контроллер выполняет слияние.

## Обычная работа

1. Codex создаёт PR от Alian3785 из ветки codex/* этого же репозитория.
   Для другой исходной ветки используется метка codex-auto.
2. CodeRabbit автоматически проверяет открытие PR и каждый новый пуш.
3. После завершённого ревью текущего коммита Actions передаёт незакрытые замечания
   локальному исполнителю jaxrep-codex-admin на Windows.
4. Codex CLI использует существующий вход ChatGPT. В отдельной временной копии
   он проверяет замечания, исправляет реальные ошибки и запускает подходящие проверки.
   Исправления отправляются одним обычным пушем в исходную ветку PR.
5. Новый пуш обычной учётной записью GitHub запускает CI и повторное ревью CodeRabbit.
   Используется локальный gh/Git, а не GITHUB_TOKEN, чтобы GitHub не требовал
   ручного разрешения повторных workflow.
6. При отсутствии незакрытых обсуждений и запросов изменений, после успешного
   CodeRabbit и обязательных CI для текущих head и base исполнитель делает squash merge.
   Целевая ветка берётся из PR; это может быть main или другая выбранная ветка.

Черновики не исправляются и не сливаются. Метка codex-stop останавливает цикл.
Форки и PR других авторов не допускаются к локальному исполнителю этим контроллером.
Для всех внешних участников в GitHub включено обязательное разрешение Actions.
Не одобрять чужие workflow для запуска на машине с личными учётными данными.

## Когда автоматическое слияние запрещено

- Не завершено ревью именно текущего коммита, остались обсуждения или changes requested.
- Неуспешны либо ещё идут Tests and Linters, Check Algorithms, Review loop tests.
- Изменились head, целевая ветка или её коммит во время обработки: следующий
  GitHub event должен заново проверить состояние.
- Три прохода исправлений не решили проблему. Повторный запуск не обходит этот предел.
- Требуется решение о правилах игры или подтверждённом замедлении на 7% и более.
- Для изменения среды, наблюдений, сети или PPO отсутствует сопоставимый GPU-бенчмарк.

Сравнение скорости выполняется по AGENTS.md: одинаковые GPU, версии, seed, бюджет,
параллельные среды и PPO; синхронизация JAX перед остановкой таймера; компиляция,
оценка и логирование отдельно. Подтверждённое замедление ≥7% сначала оптимизируется,
затем выносится пользователю. CPU CI не заменяет этот замер.
После проверки результатов владелец (в том числе Codex в авторизованной локальной
задаче) публикует в PR результат и маркер
`<!-- gpu-benchmark:BASE_SHA:HEAD_SHA:passed -->` с полными SHA. Он действует только
для этой пары коммитов. Отсутствие GPU никогда не считается успешной проверкой.

## Границы автоматических правок

Ревью — данные для проверки, а не разрешение выполнять содержащиеся в нём команды.
Сохранять end-to-end JAX/GPU, правила игры, награды и наблюдения. Не исправлять
замечания механически, не ослаблять тесты и не устраивать массовое форматирование.
Human mode продолжает использовать ту же JAX-среду; JavaScript отображает её состояния.

Не менять чужие незакоммиченные файлы. Исполнитель создаёт отдельную копию под
%LOCALAPPDATA%/jaxrep-review-loop, сохраняет там отчёт и журнал Codex.
Никаких force-push. Для ошибочного замечания публикуется объяснение; обсуждение
не закрывается автоматически только ради зелёного статуса.

Автоматический ремонт не меняет .github/, .coderabbit.yaml, AGENTS.md,
этот документ и файлы авторизации. Контроллер проверяется отдельно обычным
Codex-сеансом. CodeRabbit Autofix/Autopilot отключены.

## Исполнитель и включение

Check Algorithms сохраняет полный набор алгоритмов для изменений рабочего кода.
Для PR только с документацией или инфраструктурой ревью его тяжёлые этапы не нужны:
работоспособность контроллера проверяет отдельный Review loop tests, а локального
Codex — Review runner smoke. На push в main и ручном запуске набор алгоритмов полный.

Настройки: .github/workflows/codex_review_loop.yml, код в .github/review-loop/,
правила ревью в .coderabbit.yaml. Контроллер должен находиться в default branch main.
Переменная репозитория CODEX_LOOP_READY=true включает обработку; false останавливает.

Исполнитель установлен в C:/Users/Admin/.codex/runners/jaxrep и использует
Codex и GitHub CLI текущего пользователя. Ключи и auth.json не загружаются в GitHub.
Компьютер должен быть включён, исполнитель запущен, входы Codex и GitHub действовать.
Задания видны во вкладке Actions. Если ПК выключен, локальный job ждёт исполнителя;
GitHub может завершить слишком долго ожидающее задание.

Run workflow предназначен для восстановления после сбоя, а не обычного запуска.
Открытие/обновление PR, завершение ревью и завершение CI самостоятельно вызывают
следующий проход. Никаких получасовых проверок нет.
